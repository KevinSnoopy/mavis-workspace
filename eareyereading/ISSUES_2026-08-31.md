## 1. 设置页：内置语音引擎解压阶段仍硬编码显示「正在下载…请保持网络连接」

### 现象
- 在设置页"语音"段下载内置 TTS 模型。
- 下载完成进入"解压"阶段后（_downloadProgress = Extracting(...)），
  - 卡片**内部**进度条下方文字正确显示"解压中 (xxx/yyy) <filename>"（这部分对）。
  - 卡片**底部**的另一个 `SettingRow`（图标 Downloading）仍硬编码显示 **"正在下载..." / "请保持网络连接"**，
  - 整张卡片视觉上同时给用户"在下载"和"在解压"两个互相矛盾的信号。

### 根因（代码定位）
- 文件：`app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt`
- 区间：`905-912` 行
- 摘录：
  ```kotlin
  if (uiState.embeddedDownloading || uiState.embeddedInitializing) {
      SettingRow(
          icon = Icons.Default.Downloading,
          iconBg = SurfaceSecondary,
          iconColor = OnSurfaceTertiary,
          title = if (uiState.embeddedInitializing) "正在初始化..." else "正在下载...",
          subtitle = "请保持网络连接",
      )
  }
  ```
- 该 `SettingRow` 与卡片内部 `864-878` 行的 `LinearProgressIndicator` 是**两个独立 UI 组件**，
  各自维护状态。底部 `SettingRow` 没接 `embeddedDownloadStage`，
  也没区分 `EmbeddedTtsEngine.Progress.Extracting` 阶段。

- 顺带影响阅读页弹窗 `TtsInstallDialog`（`ReaderScreen.kt:494-495`）：
  ```kotlin
  text = downloadStage
      ?: "正在下载内置 TTS 模型 ${(progress * 100).toInt()}%…请保持网络，不要关闭应用",
  ```
  fallback 文案是兜底逻辑，理论上 `downloadStage` 不为 null 时不会触发。
  但若 ViewModel collect 阶段切换瞬间 `stage == null`，
  进度条刚切到"解压中"前那一帧会闪过这行"请保持网络"。
  （待确认是否实际可见）

### 期望行为
- 解压阶段：底部 `SettingRow` 的 title 改为"正在解压"或直接隐藏，
  subtitle 改为"解压中…（无需联网）"或留空。
- 初始化阶段：title 改为"正在初始化"，subtitle 改为"无需联网"。

## 2. 内置语音引擎：解压时文件数量统计的预扫分母 bug

### 现象
- 解压 Piper 归档时，进度条可能永远到不了 100%，停滞在 99.x%。
- 体感：解压阶段进度条长时间不动，用户误以为卡死。

### 根因
- 文件：`app/src/main/java/com/eareyereading/tts/EmbeddedTtsEngine.kt`
- 两个函数对"什么算 entry"的口径不一致：
  - `countTarEntries`（851-868 行，预扫）：**所有 entry 都 +1**（不区分 file/dir/其他类型）
  - 解压循环（1007-1012 行）：**只数 `entry.isFile || entry.isDirectory`**，跳过 symlink/fifo 等
- 后果：归档里如果包含 symlink（实际 Piper 的 `espeak-ng-data/phonindex` 等就是 symlink），
  分母（预扫）> 分子（解压），进度永远到不了 1.0。

### 期望行为
- 预扫与解压循环用同一套过滤条件，统计口径一致。
- 建议抽一个 `shouldCountTarEntry(entry, canonicalRoot): Boolean`，
  两个调用点共用，分母分子口径永远一致。

### 详细分析
见用户上一轮会话中的 5 条 bug 报告：
- Bug 1（P0）：预扫/解压过滤口径不一致 → 进度卡 99%
- Bug 2（P2）：预扫无路径校验（与 Bug 1 配对出现）
- Bug 3（P2）：目录条目计入"文件数"，UI 体感偏差
- Bug 4（P1）：预扫失败时末态分子分母差 1，UI 不收敛
- Bug 5（P3）：异常态 UX 跳变

### 涉及文件
- `app/src/main/java/com/eareyereading/tts/EmbeddedTtsEngine.kt:851-868`（`countTarEntries`）
- `app/src/main/java/com/eareyereading/tts/EmbeddedTtsEngine.kt:967-980`（动态分母兜底）
- `app/src/main/java/com/eareyereading/tts/EmbeddedTtsEngine.kt:1007-1012`（解压循环过滤）
- `app/src/main/java/com/eareyereading/tts/EmbeddedTtsEngine.kt:1045-1052`（末态 push）

## 3. 阅读主题 与 外观模块的「深色模式」冲突

### 现象
- 设置页同时存在两套主题控制：
  - **「阅读主题」**（807-831 行，ReadingTheme 枚举：LIGHT / DARK / SEPIA）：控制阅读页背景/文字配色。
  - **「外观 / 深色模式」**（971-978 行，`uiState.darkMode` 开关）：控制整个 App 的 MaterialTheme 主题。
- 两套系统**未联动**：
  - 用户在"外观"里关掉深色模式，App 切到浅色 MaterialTheme；
    但如果之前在"阅读主题"里选了 DARK，阅读页背景仍用 `DarkBg`（硬编码 Color，不跟 MaterialTheme 走）。
  - 反之：用户在"阅读主题"里选 SEPIA，但 App 全局仍是浅色 MaterialTheme，
    弹窗/对话框/设置页列表跟阅读页主题不一致，整体视觉割裂。
- "深色模式"开关打开/关闭，**阅读页背景不变**；用户预期是"App 全深色 + 阅读页深色背景"。

### 根因（代码定位）
- 文件：`app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt`
- 阅读主题（ReadingTheme）：
  - 807-831 行：阅读主题 FilterChip 选择器，调用 `viewModel.setTheme(theme)`
  - 设置项定义在"阅读"卡片内
- 外观深色模式（darkMode）：
  - 967-990 行："外观"段，"深色模式" Switch
  - 调 `viewModel.setDarkMode` 写 DataStore `DARK_MODE`
- 阅读页背景渲染（`ReaderScreen.kt:102-111`）：
  ```kotlin
  val backgroundColor = when (uiState.theme) {
      ReadingTheme.LIGHT -> MaterialTheme.colorScheme.background
      ReadingTheme.DARK -> DarkBg         // 硬编码
      ReadingTheme.SEPIA -> SepiaBg       // 硬编码
  }
  ```
  `DarkBg` / `SepiaBg` 是 `ui/theme/Color.kt` 里的硬编码常量，
  与 `MaterialTheme.colorScheme` 是**两套独立色彩系统**。
- MaterialTheme 在 `MainActivity` / `Theme.kt` 里根据 `darkMode` 切换。

### 用户要求
- **直接把"外观"模块（971-990 行的整个"外观"段）移除**。
- App 主题完全由"阅读主题"控制：
  - LIGHT → App 浅色 MaterialTheme + 阅读页浅色
  - DARK → App 深色 MaterialTheme + 阅读页深色
  - SEPIA → App 浅色 MaterialTheme + 阅读页 sepia 背景（保留）
- `darkMode` 字段在 DataStore 里可保留兼容旧数据，但 UI 不再暴露。
- 移除时需注意：
  - `viewModel.setDarkMode` 函数（422 行附近）保留兼容层（写 DataStore 但 UI 不调）
  - 或彻底删除：注意 grep 所有调用方
  - `MainActivity` 里基于 `darkMode` 选 `darkColorScheme`/`lightColorScheme` 的逻辑可改为永远读 ReadingTheme

### 涉及文件
- `app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt:965-990`（"外观"段，含深色模式 + Collins 高亮）
- `app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt:422-425`（`setDarkMode` 函数）
- `app/src/main/java/com/eareyereading/ui/screens/reader/ReaderScreen.kt:102-111`（阅读页背景渲染）
- `app/src/main/java/com/eareyereading/ui/theme/Theme.kt`（MaterialTheme 切换逻辑）
- `app/src/main/java/com/eareyereading/data/repository/SettingsRepositoryImpl.kt:89-91`（DataStore `DARK_MODE` 写入）

## 4. 高亮 Collins 等级：直接打开并不可修改

### 现象
- 在设置页"外观"段，"高亮 Collins 等级"开关默认**开启**（`collinsHighlight` 默认 `true`）。
- 用户反馈"直接打开并不可修改"：
  - 用户尝试关闭后，进入阅读页词频颜色**仍然显示**（无变化）。
  - 用户尝试重新打开/关闭多次，行为不一致。

### 根因（代码定位）
- 文件：
  - `SettingsScreen.kt:980-987`（Settings 端的"高亮 Collins 等级"开关）
  - `SettingsScreen.kt:56`（`_uiState.collinsHighlight` 默认 `true`）
  - `SettingsScreen.kt:442-444`（`setCollinsHighlight` 写 DataStore）
  - `SettingsRepositoryImpl.kt:83-84, 99-101`（DataStore 读写，默认 `true`）
  - `ReaderViewModel.kt:126`（Reader 的 `showWordLevelColors` 默认 `false`）—— **独立字段，没读 DataStore**
  - `ReaderViewModel.kt:1768-1770`（`toggleWordLevelColors` 只改内存 `showWordLevelColors`，**不写 DataStore**）
  - `ReaderScreen.kt:1930-1936`（阅读页内的"Collins 词频色彩" Switch，调 `toggleWordLevelColors`）

### 状态分裂
- Settings 端：
  - 字段 `collinsHighlight`（DataStore 持久化），UI "高亮 Collins 等级" Switch。
- Reader 端：
  - 字段 `showWordLevelColors`（ReaderViewModel 内存），UI "Collins 词频色彩" Switch。
- **两个字段互不感知**：
  - Settings 开 collinsHighlight=true，进入 Reader，showWordLevelColors 仍是 false（默认），
    词频颜色不显示，用户以为"开关没生效"。
  - Reader 内手动开 showWordLevelColors=true，离开/重启 ReaderViewModel 后回 false，
    用户以为"开关被自动关了"。
  - Reader 内关 showWordLevelColors=false，回到 Settings，collinsHighlight 仍是 true，
    用户以为"关不掉"。

### 期望行为
- 短链：把"高亮 Collins 等级"开关砍掉（参见第 3 节：用户已要求砍掉"外观"段）。
- 中链：合并为单一字段，Reader 端 init 时从 DataStore 读 `collinsHighlight`，
  写时回写 DataStore。
- 等级语义：当前实现只是 on/off，但 Collins 实际有 5 级（核心/进阶/提高/进阶高/罕用）。
  若后续要做"等级选择器"，应改成 1-5 星 Slider / SegmentedButton。

### 用户要求
- **直接把"外观"段（含此开关）移除**。
- Collins 词频颜色的入口保留在阅读页内（"Collins 词频色彩" Switch），
  仍走 ReaderViewModel 内存的 `showWordLevelColors`（不持久化，体验上保持"在阅读页内调"）。
  若后续要持久化，再单独做。

### 涉及文件
- `app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt:980-987`（要被移除的 Switch）
- `app/src/main/java/com/eareyereading/ui/screens/settings/SettingsScreen.kt:56, 178-186, 442-444`（相关状态/函数，可保留兼容层）
- `app/src/main/java/com/eareyereading/data/repository/SettingsRepositoryImpl.kt:83-84, 99-101`（DataStore 读写，可保留兼容层）
- `app/src/main/java/com/eareyereading/ui/screens/reader/ReaderScreen.kt:1930-1936`（阅读页内 Switch，保留）
